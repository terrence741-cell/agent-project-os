# Changelog

All notable changes to Agent Project OS are documented here.

## 1.0.2 — 2026-08-16

- Added a standard shared Memory preset for new users: one physical store, a thin `MEMORY.md`, topic files created on demand, and Codex / Claude Code entry points.
- Added local Git recovery boundaries, minimal host-rule merges, and evidence-first permission proposals separated by host and read/write operation.
- Preserved exact single-file targets as higher priority; the preset never expands a user boundary unless a multi-file system is requested.
- Prohibited mirrored copies, dual-write synchronization, and force-replacing existing links or global host rules.

## 1.0.1 — 2026-08-16

- Narrowed the product to on-demand setup and repair; ordinary project work no longer routes through the plugin.
- A newly written project produces only a proposed Memory route, which requires separate confirmation.
- Rewrote first-run guidance and Skill reference so users need not learn `project-os` first.
- Completed bilingual repository Marketplace manifests for Codex and Claude Code.
- Fixed explicit Memory target boundaries: do not impose host-internal layouts or probe unapproved target directories.
- Added thin host-adapter contracts for strict path-only continuation: Codex `AGENTS.md` and Claude Code `CLAUDE.md` route to one stable entry without copying project status.

## 1.0.0 — 2026-07-31

First review candidate.

- Six Skills: low-frequency project routing, workspace bootstrap, project
  launch, explicit project check-in, structure review, and portfolio review.
- Confirm-before-write, read-only review, thin-portfolio, and sensitive-context
  boundaries verified through L0--L4 release evidence.
- Codex and Claude Code plugin manifests, Apache-2.0 license, English and
  Chinese repository overviews, and a bilingual-distribution contract.
- Explicit Codex `$project-os` invocation verified against the installed local
  plugin, with zero project-file writes.

## 0.2.0 — 2026-07-31

- Added `project-os` and `project-check-in`; completed the v0.2 behavioural
  validation cycle.

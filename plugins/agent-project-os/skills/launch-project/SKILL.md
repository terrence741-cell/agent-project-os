# 启动项目

创建能让后续 Agent 可靠续接的最小项目结构。不要强加通用文件夹模板，也不要因细节缺失而无法提供有用的首次回复。

## 1. 建立安全读取范围

使用用户提供的路径与读/写边界。目标路径已知时，提出变更前先以只读方式检查；否则仅基于项目描述，并把缺少路径标记为写入的阻塞性缺口。

在项目根目录寻找稳定入口、当前状态、源材料、决策和交付物。将作为证据使用的精确路径写明。除非用户明确指定，不得把嵌套的 `测试`、`test`、`fixtures`、`examples`、`archive`、`归档`、供应商提供或生成目录作为活跃项目证据。

除非得到确认，草稿、旧引述、会议记录和无日期材料都应视为参考，而非当前事实。用户描述的既有材料若不在可读范围内，标记为**未知 / 需验证**；绝不改写成“未开始”“无活跃工作”或“未分配”。

## 2. 交付只读启动包

首次实质回复时，即使信息不全，也给出有用的启动包。不得进行文件系统写入、Memory 更新、索引变更或外部行动。

只包含当前情境有用的部分：

1. **已知事实**：提取用户提供的事实和已检查证据，证据与推断分开。
2. **临时三维分类**：说明工作形态（目标导向、运营或混合）、服务协议（交付推进、持续运营、长期陪伴）和成熟度（空白概念、材料散乱、可运行但混乱、成熟/可续接）；各项给出简短理由，未支持部分标为临时。
3. **关键缺口**：只问会改变安全、结构或下一步行动的事实。若能安全地留在当前状态记录中，缺口就不是阻塞性。
4. **第一步行动**：建议一个具体、可逆、在完整系统建立前就能创造价值的下一步。
5. **拟议产物**：目标路径已知时，列出精确路径的最小创建/变更；否则展示路径模式并说明最终路径需确认。每个产物说明用途，以及它是稳定规则来源、当前状态来源，还是现有证据的路径。拟议稳定入口必须写明项目读取范围、敏感内容边界，以及永不得提升至工作区 Memory 或 Portfolio 的内容。
6. **确认门**：要求明确批准目标路径、边界和所列写入，并仅合并最少的阻塞性问题。

不得虚构节奏、负责人、指标、流程、平台、体量、健康事实或其他用户拥有的事实。把假设标为假设。不要用固定问卷，也不要在提出安全最小方案前要求所有未来可能有用的信息。

### 问到足以运行，而不只是足以建文件

用户要的是持续项目系统时，不要只问目标和路径就停下。启动包中按高影响缺口分组，让用户可在一条回复中回答。只问与临时服务协议相关的组：

| 需要 | 何时询问 |
| --- | --- |
| 结果与范围 | 什么结果或改变重要、什么不在范围内、什么算有用的第一阶段？ |
| 起始现实 | 已有什么、当前发生什么、现在重要的约束/期限/阻塞是什么？ |
| 所有权与权限 | 谁决定、贡献或必须批准关键选择？ |
| 位置与权限 | 项目可放哪里、可读写什么、哪些不可触碰？ |
| 连续性 | 新会话应恢复什么、什么规律或触发条件应引起一次 check-in？ |
| 协议特定需求 | 交付：利益相关者、交付物、时间；运营：当前队列、节奏、信号/指标；长期陪伴：服务对象、隐私、决策权、升级边界。 |

将它们呈现为紧凑、量身定制的问题组，而非必填表。省略已回答问题；非阻塞细节延后到**待补全上下文**。为安全写入所必需的问题标为阻塞；否则说明以后何种任务会触发它。

长期陪伴项目必须明确服务对象、所有者决策权、隐私边界、重复节奏和专业升级边界。不要替所有者作医疗、学校、法律或其他高风险决定。

## 3. 保留成熟项目；先分类再变更

用分类选择回应，而非套模板：

| 情况 | 默认回应 |
|---|---|
| 目标导向工作 | 仅在既有结构缺少时，提议一个当前进度记录加稳定入口。 |
| 运营或混合工作 | 提议最小有用的当前运营记录、队列、周期审阅或活跃事项路径；不要强行建立线性进度文件。 |
| 成熟且可续接 | 已有稳定入口、当前状态、材料路由和清晰下一步时，建议保留或直接接手；引用证据，不要重建。 |
| 可运行但混乱 | 找出最小缺环，提出最小调整，而非整体重构。 |

每项提议都必须原地保留原始证据。通过入口文件路由至既有来源，而不是复制完整内容。若需记录非阻塞未知项，只写入权威当前状态位置的**待补全上下文**，且包含：缺少的事实、其重要性、何时提问以及待确认的来源/人员。

## 4. 仅在明确确认后写入

要求用户明确确认目标路径、允许边界和拟议写入清单。泛泛地说“启动项目”并不等于确认具体文件方案。

确认后：

1. 重新检查目标路径中会影响提议的变更。
2. 只创建或修改已批准的产物。
3. 稳定规则留在稳定入口；当前事实和下一步留在权威当前状态记录；来源位置应作为路径而非复制事实。稳定入口中写明项目的 Memory 范围：可读项目边界、敏感内容排除项和未来 Memory 候选允许使用的任何路径。
4. 将非阻塞未知项写入该当前状态记录，不要散落在审阅、复盘或来源笔记中。
5. 报告精确变更路径、实际变更及与批准方案的所有偏离。

启动过程中绝不覆盖 Memory 或既有项目状态。不得批量重构、删除、移动或执行外部行动。

## 5. 验证新会话交接

获批准写入后，使用新会话或等价隔离上下文。仅提供项目路径，并要求它识别：

1. 目标；
2. 当前状态；
3. 下一步；
4. 接下来要读取的材料；以及
5. 不得跨越的边界，包括项目-Memory 范围与敏感内容排除项。

只有确认时已包含此写入，才能把结果记录在已批准的项目位置。若项目无法回答任一项，识别最小缺环并提出修正；不要悄悄扩展结构。

## 安全规则

- 用户拥有的事实应留在原始来源，除非明确批准提升。
- 标明不确定性与推断；建议或审阅发现不是项目事实。
- 确认前不得写入，包括空文件夹、模板、索引或状态文件。
- 完成工作会话时，只更新已批准的当前状态位置，并说明下一次续接点。

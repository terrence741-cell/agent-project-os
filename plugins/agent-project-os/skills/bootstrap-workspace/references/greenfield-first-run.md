# Greenfield First Run

仅用于明确的全新用户：没有 Workspace Memory、不理解项目方法，并希望从真实工作建立第一个可续接项目。若在获授权范围内发现已有 Memory，停止 Greenfield 流程，回到 `SKILL.md` 的保留优先模式；不默认迁移。

## 交互规则

- 每轮最多问一个问题。用户主动一次回答多项时，接纳已有答案，不重复追问。
- 不展示 Skill 清单、抽象模型或完整问卷；不要求用户选 Skill 或项目类型。
- 确认前只在对话中保留工作笔记；不创建目录、空文件、Memory、宿主入口或 Git 恢复点。
- 不扫描电脑、其他工作区、聊天、云盘或未授权目录。

## 逐轮流程

1. 用两句白话定向：“Memory 保存长期有效的工作习惯和项目位置；Project 保存一件持续工作现在做到哪里。我们先只建一个真实项目，每次确认一件事。”然后只问用户最近反复推进的 2–3 件真实工作。
2. 根据持续时间、是否会多次续接、是否有独立目标和资料，推荐其中 1 件作为第一个项目，用一两句解释理由，然后只请用户确认。默认只建这 1 个项目，不顺手搭建其余项目。
3. 项目确认后再逐轮确定文件位置与宿主。先问用户希望把文件放在哪里；若用户不知道路径，只把当前打开的工作区作为候选解释并请求确认，不扫描其他目录。宿主选择只问“仅 Codex”“仅 Claude Code”或“两者”；只为用户选择的宿主提议入口。用户确认宿主后，下一问必须进入第 4 步的读取／写入边界，例如“允许读取什么、允许后续提议写入什么、明确禁止什么？”不得改问是否检查候选路径；“是否允许我检查这个路径”不算边界确认。候选路径是否存在只能在用户随后明确授权的范围内确认。
4. 逐轮确认允许读取和拟议写入的精确位置，以及不得读取或写入的区域。目标位置只获写入指定时，不得提前探测；需要读取现有内容时单独请求最小授权。
5. 逐轮补齐安全运行必需的最少信息：项目名与用户明确提供的别名、目标与范围、已有材料与当前状态、下一步、项目位置和隐私边界。只有当称呼、主要身份或稳定偏好确实会改变本次 Memory 内容时才追问，且仍每轮一题。若项目事实和边界已齐、只剩会进入长期 Memory 的身份或稳定偏好，可合并问一个概念明确的问题：“你希望长期 Memory 记录哪些稳定身份和协作偏好？”用户回答后立即进入第 6 步，不再追问额外隐私范围，也不在正式精确提案前先给一套非正式提案。用户已经给出目标、当前状态、下一步、材料现状、项目位置、隐私边界以及会进入 Memory 的身份与稳定偏好时，信息已足够；不得为了补齐可选的“包含／不包含”描述再问一个不阻塞的问题。
6. 把已确认信息作为 **Greenfield First Run 交接包**，读取 [launch-project](../../launch-project/SKILL.md)，并进入其 First Run 内部交接模式。交接包只含用户已提供或确认的事实、授权边界、所选宿主和待确认未知；不把推断写成事实。对用户不暴露 Skill 切换或要求再次调用。
7. `launch-project` 展示项目根、稳定入口、唯一当前状态、所选宿主的项目级薄入口及精确拟写内容后，只请用户批准这组**项目写入**。同一目标在提案中只能出现一次；提案结束后必须明确问一个批准问题，不得只展示内容后等待用户自行推断下一步。
8. 项目写入后，对用户所选的每个宿主使用**非持久的隔离 HOME、临时 profile、命令行配置覆盖或等价隔离上下文**运行路径式毕业测试；不得为测试修改用户真实插件配置、卸载插件或删除缓存。若宿主只能通过持久配置禁用插件，先展示精确配置改动并取得单独批准；无法安全隔离时，标记“路径式毕业测试待执行”并给出手动方法，不得声称已通过。
9. 项目通过路径式测试后，内部恢复 `bootstrap-workspace` 的项目路由登记模式：先核验稳定入口，再检查目标 Memory 中的名称、别名、路径与范围冲突。随后读取 [标准共享 Memory preset](shared-memory-preset.md)，把拟议变更分为六个权限桶：Memory 内容、物理结构、宿主入口、宿主全局规则、宿主访问权限、Git 恢复。逐桶使用这些中文名称说明范围；所有桶标题和解释都放在批准块之外。批准块内部只能出现 `FILE`／`SYMLINK` 声明、每个 `FILE` 对应的一个完整代码块，以及 `NO_CHANGE ACCESS`／`NO_CHANGE GIT`；`SYMLINK <路径> -> <目标>` 这一行已经是完整声明，后面不得附代码块或说明。所有拟写目标必须汇总为一份可完整批准的清单，每个文件或软链接恰好出现一次；物理结构桶只说明哪些目录和按需文件由内容桶创建，不得把同一文件再声明一遍。宿主入口和规则必须使用用户已确认的精确目标，不得自行追加 `.codex`、`.claude` 或其他层级。提案结束后只问一个批准问题。用户可在同一轮批准多桶，但必须逐项点名。项目批准绝不得替代任何一桶的批准。
10. 获得对应批准并写入后，再使用与第 8 步相同的非持久隔离方式，只输入“继续<项目名>”验证名称式续接；无法安全隔离时标记待执行，不伪装完成。
11. 两项毕业测试通过后，只教 2–3 条普通说法，例如“继续<项目名>”“这个项目下一步是什么”“把这次确认的进展更新到项目状态”。明确告知：以后继续项目不需要调用 Agent Project OS；只在新的搭建或结构检修需求时再使用。

## 完成门

First Run 只有在以下条件全部满足时才完成：

- 仅建立 1 个用户确认的真实项目；
- 项目与 Memory 的精确写入已分别批准；
- 只为用户所选宿主建立入口，多宿主共用同一物理 Memory；
- 路径式和名称式续接均在禁用插件时通过。任一测试待执行时，First Run 仍属未毕业；
- 没有将当前优先级、客户动态、项目待办或敏感事实提升到长期 Memory。

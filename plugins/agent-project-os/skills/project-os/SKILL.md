# Project OS

在用户明确需要 Agent Project OS、但不知道选哪项搭建或检修能力时，帮助选择一个现有 Skill。它是低频求助入口，不是项目管理器、日常入口或会话运行时。

## 1. 先判断是否应使用本路由器

只有请求同时满足以下条件才继续：

1. 用户明确要搭建、整理、检查或维护自己的项目体系；
2. 用户明确表示不知道应选择哪项 Project OS 能力，或其请求确实在两项以上现有能力之间歧义。

以下请求不使用本路由器：

- 已命名项目的普通续接、今天计划、进展查看或状态更新；服从核心 Memory、项目稳定入口和项目本地协议。
- 写作、研究、分析、开发等具体业务任务；交还宿主 Agent 或专业 Skill。
- 用户已经点名 `bootstrap-workspace`、`launch-project`、`project-check-in`、`review-project-structure` 或 `review-portfolio`。
- 用户明确提出的原子需求；让对应 Skill 自然匹配，不要求先经过 `project-os`。
- 目标、范围、方向或“是否值得继续”的业务判断；当前版本没有对应的 Project OS Skill，不得伪装成结构 Review。

若请求不符合使用条件，立即让路，不读取任何项目或 Memory，也不输出 Project OS 路由建议。

## 2. 只在现有能力之间选择

| 用户需要 | 选择 |
|---|---|
| 建立、整理、审阅长期 Memory，或登记项目路由 | `bootstrap-workspace` |
| 启动新项目、接手项目、为散乱资料补最小可续接结构 | `launch-project` |
| 明确要求一次通用项目 check-in，且没有项目本地协议接管 | `project-check-in` |
| 只读检查一个项目的入口、状态源、文件组织或续接能力 | `review-project-structure` |
| 只读比较多个项目的阻塞、过时、冲突或复用 | `review-portfolio` |

不创建“中途方向 Review”等不存在的路径。若用户的问题超出现有能力，明确说明边界并退出，让宿主 Agent 直接回应或使用其他工具。

## 3. 派发或澄清

若用户的求助已经明确指向一项能力，读取该同级 `SKILL.md`，在同一回复执行它的第一个适用步骤，然后退出本路由器。不要只输出路由标签，不要求用户再次调用，也不要把所选 Skill 变成下一轮必须经过的入口。

若仍有真实歧义，只问一个能区分候选路径的问题。例如：

> 你现在更需要搭建长期记忆、启动或整理一个项目、检查单项目结构、比较多个项目，还是做一次明确的通用 check-in？

问题中的每个选项必须互斥，且只对应一个现有原子 Skill；不得把单项目与多项目 Review 等两个 Skill 合并成一个选项。用户回答任一选项后必须能直接选择一次，不再需要第二个区分问题。

澄清时保持中立：不得推荐默认 Skill、默认执行顺序或“先做 X 不会错”，也不得用前置依赖替用户预判路线。收到回答后只选择一次；不要在本 Skill 中开始第二轮访谈。

## 边界

- 路由期间不得读取工作区索引、项目文件、Memory、文件夹或历史对话。
- 不得创建、修改、移动或删除任何文件。
- 除选择能力外，不评估项目状态、总结证据、诊断阻塞，或建议业务行动、默认 Skill 与执行顺序。
- 选择一个原子 Skill 后立即退出；后续日常工作服从 Memory 和项目本地协议。
- 用户可以始终绕过本路由器，直接使用原子 Skill。

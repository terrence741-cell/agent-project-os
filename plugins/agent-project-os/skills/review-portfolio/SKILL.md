# 审阅项目组合

审阅项目间的关系，但不把审阅变成一个新的项目数据库。项目组合视图是路由和决策辅助；每个项目仍是自身状态与工作的事实来源。

## 1. 确定审阅视角

询问或确认：

- 工作区根目录，以及获授权的项目索引或入口；
- 审阅目的（如解除交付阻塞、发现过时工作或寻找复用）；
- 相关时间范围及该语境下“过时”的定义；
- 审阅中排除的任何项目、文件夹或敏感区域。

默认只读。没有精简索引时，不要扫描每个项目。要求一组有边界的项目入口，或提出最小索引字段：项目名称、类型、状态摘要、最后更新日期、入口路径，以及可选的负责人/依赖/标签。

## 2. 在项目内容前读取精简证据

从范围内明确指定的工作区项目导航、索引条目、frontmatter 或状态摘要开始。为每项观察记录来源。

不要加载每个项目的正文。只有索引证据不足以回答一个直接、与决策相关的问题时，才请求或读取单一项目的特定来源。说明下钻原因，并保持用户的范围限制。

## 3. 评估跨项目信号

仅使用有支持的证据识别：

| 信号 | 何种内容算证据 | 处理 |
| --- | --- | --- |
| 阻塞 | 明确的依赖、等待状态、负责人瓶颈或缺少必需输入 | 关联至受影响项目条目 |
| 过时风险 | 最后更新日期或状态明确超出约定时间范围 | 陈述日期和阈值；不得推断已放弃 |
| 冲突 | 对共享资源、负责人、截止日期或决定存在不相容主张 | 展示两个来源；不裁定胜者 |
| 复用机会 | 重复的工具、模板、资产、工作流或已证明能力 | 描述候选项和支持它的项目 |

缺少证据不是负面发现。标为“无法从索引判断”，且只有会改变决定时，才提出范围狭窄的下钻问题。

## 4. 产出项目组合报告，而非替代数据库

返回以下部分：

1. **项目组合快照**：范围、审阅视角，以及基于索引的紧凑计数或分组。
2. **需要关注**：阻塞、过时风险和冲突，每项附证据与来源路径。
3. **复用机会**：有支持的候选项、受影响项目及预期收益。
4. **建议的下一步检查**：应查的具体项目来源、原因以及可回答的问题。
5. **项目交接**：行动属于命名的项目来源；列出每项行动应带往何处。
6. **限制**：排除的项目、缺少的字段和无法判定的发现。

每项行动都要标明拥有它的项目。不要创建新的权威状态表、把项目组合观察改写为项目事实，或修改项目文件，除非用户另行要求一个具体改动。

## 护栏

- 默认只读并采用精简索引审阅。
- 不要递归检查工作区或加载所有项目正文。
- 不要根据缺失字段编造日期、负责人、依赖或原因。
- 不要解决跨项目冲突；报告来源并请相关负责人决定。
- 不要把项目组合结论保存成一套与项目事实竞争的系统。

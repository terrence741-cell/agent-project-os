# 状态交接

仅在用户明确要求一次**状态交接**时，把已确认的项目更新转成一个下一步和一份可审阅的最小状态修改。它是按需维护工具，不是日常项目入口。

## 0. 适用性门

开始前确认：

- 用户显式调用本 Skill，或明确要求“使用 $state-handoff / 把这次更新整理成状态交接”；
- 已提供项目路径与允许读取的边界；
- 项目没有更具体的本地更新协议接管，或稳定入口明确允许使用通用状态交接。

若只是普通续接、今天计划或进度更新，让核心 Memory 和项目本地协议处理，不运行本 Skill。若项目已有自己的更新协议，服从该协议，不强加本 Skill 的输出结构，也不创建平行状态源。缺少项目路径或读取边界时，只询问这一项；不要读取全局 Memory 猜测位置，也不要在无证据时给出项目状态提案。

## 1. 建立项目边界

只读取：

1. 项目稳定入口；
2. 入口点名的唯一当前状态；
3. 仅在理解本次更新确有必要时，读取入口明确路由的相关材料。

说明精确读取路径。不得扫描同级项目、整个工作区、归档、聊天或全局 Memory。项目证据强于最近对话；没有项目证据支持的主张标为**用户陈述 / 等待确认**。

若稳定入口或状态缺失、冲突或不足以安全更新，准确说明无法恢复什么并保持只读。结构本身需要检查时建议 `review-project-structure`；需要建立或实际修复最小结构时建议 `launch-project`，但不在本 Skill 中执行。

## 2. 处理明确更新

只处理用户本次明确提供的进展、阻塞、决定、约束变化或新事实：

- 区分项目已有事实、用户新陈述、推断和未知。
- 说明该更新是否改变当前状态、下一步、开放决定或阻塞。
- 数字缺单位、货币、分母或范围时保持缺失，不自行补全。
- 开放决定保持开放；用户提到的人或选项不自动成为完整候选集。
- 不把建议、预测或 Agent 诊断写成已确认事实。

返回：

1. **我的理解**：项目证据、用户陈述和不确定性。
2. **下一项安全行动**：准确一项；只有它受阻时才问一个范围狭窄的问题。
3. **关注 / 决定**：只列实质依赖、风险或所有者决定。
4. **拟议状态更新**：目标路径、精确新增或替换文本、每项新事实来源，以及新会话恢复所需的最小信息。

不得因一次状态交接新建日报、模板、第二状态文件或其他平行事实源。

## 3. 确认后才写入

展示精确目标文件与精确修改内容后等待。只有用户同时确认两者才继续。

写入前重新读取目标，只应用已确认的最小改动；保留冲突、未知和未确认主张原状。写入后报告精确路径、实际修改和下一次续接点。

确认前不得创建、修改、移动或删除项目文件；不得更新 Workspace Memory、索引、Portfolio 或无关项目。出现稳定的跨项目经验时，只能作为候选交给 `bootstrap-workspace`，不能在本 Skill 内提升。

## 边界

- 不判断项目方向、范围、目标是否仍合适或是否值得继续；明确说明该问题超出本 Skill。
- 不比较多个项目，不做结构 Review，不启动或重组项目。
- 不代替用户诊断、决定、发送、安排、发布或执行外部行动。
- 敏感个人、健康、儿童、客户、人事或财务事实使用最小必要摘要，并留在获批准的项目范围内。
- 完成后退出；后续普通工作继续服从 Memory 和项目本地协议。

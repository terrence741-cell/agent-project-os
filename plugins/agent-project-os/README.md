# Agent Project OS

[English](../agent-project-os-en/README.md) · [双语分发契约](../../distribution/BILINGUAL-DISTRIBUTION.md)

让 Claude Code、Codex 等桌面端 Harness Agent，真正成为你的项目协作者。

Agent Project OS 是一套开源的 Agent 项目管理系统，面向在本地文件系统中工作的桌面端 Harness Agent 用户。它帮助你把一个真实项目——无论是客户交付、内容运营、研究议题、学习计划，还是长期的个人事务——整理为 Agent 能够持续接手、理解、推进，并在会话之间安全续接的工作空间。

你不必每次开新会话都重新解释背景、翻找资料、回忆上一步做到了哪里。Agent Project OS 会引导 Agent 从项目文件中定位事实、整理当前状态、给出下一步，并在你确认后留下简洁的交接，让下一次工作可以自然续上。

## 为谁而做

**如果你刚开始使用桌面 Agent**，它帮你把一个模糊的想法或刚启动的事项，整理为一个拥有清晰目标、文件结构、当前状态和下一步行动的项目；你不需要先学会自己设计一套项目文件体系。

**如果你已经重度使用桌面 Agent**，它不会要求你迁移现有工具、重写既有资料，或把项目事实复制进另一个平台。它帮助 Agent 尊重你已有的文件结构与事实来源，在跨会话、跨周甚至跨月的工作中保持连续。

它尤其适合非代码项目的启动与长期推进：客户交付、内容生产、咨询项目、研究、运营、学习与个人计划。代码项目也能使用，但它的设计重心是那些没有成熟工程脚手架、却同样需要长期协作的真实工作。

## 它不是传统项目管理软件

它不提供任务看板、甘特图，也不替代 Notion、飞书或你的项目文件。它运行在你的工作区中，提供一组可安装的 Skills，让 Agent：

- 启动或接手一个项目；
- 在日常更新后识别当前状态与下一步；
- 审视项目结构是否真的便于长期协作；
- 在多个项目之间协助梳理优先级；
- 将已经确认、可跨项目复用的经验沉淀为长期 Memory。

项目事实始终留在项目自己的文件中；任何会写入文件的操作，都应先经你确认。

## 模型

有意分开的三层：

| 层级 | 回答什么 | 存放在哪里 |
| --- | --- | --- |
| Memory | 服务对象是谁、长期边界是什么 | 工作区 Memory |
| Project | 工作当前进展到哪里、材料在哪里 | 项目自身文件 |
| Skill | 此类工作如何被可重复地完成 | 这些 Skills |

把三层混在一起，Agent 项目就会逐渐失效：稳定入口混入易变状态会过时；项目事实被提升为长期 Memory，昨天的阻塞会比项目活得更久。

## Skills

共 6 个 Skill，你只需要先认识第一个。

| Skill | 回答的问题 |
| --- | --- |
| `project-os` | 这项请求应该走哪条路径？ |
| `launch-project` | 新项目如何获得启动包和可续接的结构？ |
| `project-check-in` | 如何将今天的更新转化为下一步行动和安全的状态交接？ |
| `review-project-structure` | 该项目结构是否真的支持 Agent 在其中工作？ |
| `review-portfolio` | 多个项目之间，哪些过时、受阻、冲突或可复用？ |
| `bootstrap-workspace` | Agent 如何理解用户是谁、工作版图是什么？ |

`project-os` 是一个轻量路由器：路由时不读取、不写入、不诊断；它选择一个工作流，并在同一轮让出位置。

## 行为保证

以下规则适用于每个 Skill，也是测试套件验证的内容：

- **未确认前绝不写入。** 每个可能写入的 Skill 会先提出精确的目标路径与内容。
- **路径缺失只阻止读取，不阻止帮助。** 即使没有项目路径，Agent 仍会根据你的描述给出一项可立即执行的具体行动，并明确标注其依据是你的说法而非项目文件。
- **审阅默认只读。** 结构审阅会返回 Keep / Change / Ignore。对于成熟项目，「保持不变」是正当且常见的结论。
- **绝不把推测写成事实。** 没有项目证据支持的说法，在确认前始终标为用户陈述。
- **项目组合保持精简。** 跨项目审阅读取索引而非项目正文；每项行动都交回给拥有它的项目。
- **敏感材料留在原处。** 个人、健康、客户、人事和财务事实都留在项目范围内，绝不建议写入 Memory。

## 安装

**Codex**：插件清单在 `.codex-plugin/plugin.json`。将此目录注册为本地插件源，并安装 `agent-project-os`。

**Claude Code**：插件清单在 `.claude-plugin/plugin.json`。将此目录添加为插件源，然后安装。

Skills 是位于 `skills/` 下的纯 Markdown。不会执行任何内容，不会进行系统级安装，也不使用网络。你也可以直接阅读任意 `SKILL.md` 并手动遵循。

## 最小首次运行

```
你：我想启动一个新项目

Agent：（同一轮进入 launch-project，返回只读启动包：它理解了什么、
       拟议的结构、你现在可做的第一步，以及它尚不知道的明确清单——
       尚未写入任何内容。）

你：前面两条对，第三条改成……然后落盘

Agent：（只写入已确认的最小内容，报告精确路径，然后进行续接测试：
       一个没有聊天记录的新会话，能否正确接手？）
```

项目已经在运行时：

```
你：这个项目超预算了，我今天只有 45 分钟，怎么办？

Agent：（根据你的说法给出一项具体的 45 分钟行动，标明尚未与项目文件核对；
       将路径作为次要问题询问，并且在获得路径前不建议改变任何状态。）
```

## 状态

V1.0.0 审核候选版本。Skills 已足够稳定，可用于真实工作；每项行为契约都由独立 Agent 连续运行 3 次（pass^3）验证，而非只验证一次。尚未公开发布到任何市场。

当前本地包为中文主包。英文国际包将作为独立命名、行为等价的产物发布；分发契约定义了两者的对等性与版本门禁。

已知的开放项以规则歧义记录在测试记录中：即两条规则允许不止一种合法解释的位置。我们记录它们，而非悄悄修改措辞，因为修补文字常会引入新的缝隙；停止条件是稳定行为，而非完美文案。

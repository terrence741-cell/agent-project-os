# 标准共享 Memory preset

仅在全新用户要求建立一套长期 Memory，或明确要求多个宿主共用一份 Memory 时使用。用户已指定单一目标文件时，不使用本 preset。

## 1. 方法与默认结构

建立一个工具中立的唯一物理库，默认候选路径为 `~/.agent-project-os/shared-memory/`。这只是候选；用户可选择其他精确路径。

```text
shared-memory/
├── MEMORY.md
├── user_profile.md
├── team_<slug>.md
├── project_<slug>.md
├── feedback_<slug>.md
└── reference_<slug>.md
```

- `MEMORY.md`：薄总索引，保存最小稳定偏好和指向主题文件的路由。
- `user_profile.md`：已确认的稳定用户画像。
- `team_<slug>.md`：团队或业务线的稳定背景与边界。
- `project_<slug>.md`：项目名、别名、根路径、稳定入口、范围和来源；不保存项目当前状态。
- `feedback_<slug>.md`：已确认、跨项目稳定的协作反馈。
- `reference_<slug>.md`：持久有效的基础设施或参考说明。

只创建有已确认内容的文件。不为了补齐模板创建空文件，不把每日进度、项目待办、未确认判断或敏感事实提升到 Memory。

## 2. 用户所选宿主

只为用户明确选择的宿主提议入口。若只选 Codex，不提议 Claude Code 入口；若只选 Claude Code，不提议 Codex 入口。选择多个宿主时，它们必须最终读写同一物理文件，不建立多份目录再同步。

POSIX 环境的默认候选：

```text
~/.codex/shared-memory  -> <physical-shared-memory>
~/.claude/shared-memory -> <physical-shared-memory>
```

不支持软链接时，让两个宿主规则文件直接指向同一物理路径。不编造未验证的平台命令。

在获得对端点的精确读取授权后，逐个判断：

- 不存在：可列为待创建软链接。
- 已是指向相同目标的软链接：保留，不重建。
- 指向其他目标的软链接，或已有普通文件/目录：报告冲突并停止；不删除，不移动，不使用强制覆盖。

## 3. 宿主启动规则

只向用户所选宿主的全局规则文件提议最小等义规则：Codex 使用 `AGENTS.md`，Claude Code 使用 `CLAUDE.md`。必须先读取获授权的现有目标，以最小合并方式提案，不覆盖其他规则。

规则语义必须包含：

1. 新会话开始时读取 `<physical-shared-memory>/MEMORY.md`。
2. 只根据当前请求继续读取其链接的相关主题文件，不全量加载整个目录。
3. 把 Memory 视为持久定向层，不视为项目当前状态的证据；状态仍以项目稳定入口指向的当前状态为准。
4. 已确认的持久偏好、稳定跨项目规则和项目路由才可回写 Memory；临时任务状态留在项目中。

如任一宿主因软链接的真实目标或物理路径不在当前可访问范围而拒绝读取或写入，先验证实际报错。然后只能在阅读当前宿主配置与当前文档后，为受影响宿主单独提议最小权限变更：写明读或写操作、物理库精确路径、精确配置文件或启动参数及最小改动。不得仅因为“可能需要”就修改配置，也不得把一个宿主的权限批准扩展到另一个宿主。

## 4. 本地 Git 恢复

在用户授权检查物理库及父路径后，判断它是否已属于一个 Git 仓库。

- 已在仓库中：使用现有仓库，不嵌套初始化。
- 不在仓库中：可单独提议本地 `git init`。
- 提交：只在用户确认要创建恢复点、且提交范围只包含本次已批准的 Memory 变更时执行。
- 不添加远程，不推送，不建立定时任务，不把备份目录当作当前 Memory。

## 5. 提案与确认范围

返回一份分范围的精确提案。若同一轮同时展示多个桶，先逐桶解释，再汇总成一份唯一的拟写清单；每个文件或软链接只出现一次，物理结构桶不得重复声明 Memory 内容桶已经列出的文件：

1. **Memory 内容**：每个目标文件的精确路径与拟写原文。
2. **物理结构**：待创建目录与按需文件；明确列出不创建的空类别。
3. **宿主入口**：每个软链接或直接引用的精确源和目标，以及已检测冲突。
4. **宿主规则**：待最小合并的精确文本；只列用户所选宿主，选择多个时分开列出。
5. **宿主访问权限**：仅在已实证需要时提案，分别列出宿主、读或写操作、精确物理路径、配置文件或启动参数及最小改动。
6. **Git 恢复**：是否初始化、是否创建本地恢复点，以及明确不做的远程操作。

用户可以一次批准多个范围，但必须明确点名。未批准的范围保持只读或未执行。

## 6. 验证

完成获批准的变更后，验证：

1. 每个已选宿主入口都解析到同一物理目录。
2. 仅当用户选择多个宿主时，验证一个宿主通过其入口写入一项获批准的合成测试变更后，其他宿主通过自己的入口读到同一内容；反向同理。
3. 每个已选宿主都先读薄 `MEMORY.md`，只按请求读相关主题文件。
4. 项目名经 Memory 路由到稳定入口和当前状态，Memory 不替代项目状态。
5. 使用非持久隔离 HOME、临时 profile、命令行配置覆盖或等价隔离上下文禁用插件后，读取链仍成立；不得为测试修改用户真实插件配置、卸载插件或删除缓存。若只能改持久配置，必须另行展示精确改动并取得批准。
6. 如建立 Git 恢复点，可用本地历史找到该变更；全程没有自动推送。
